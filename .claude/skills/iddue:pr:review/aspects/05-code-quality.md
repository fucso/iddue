# 観点⑤: コード品質

## 目的

変更後のコード全体を読み、CI では検出できない実装レベルの品質問題を確認する。
設計・要件・CI がすべて通過した後の最終レビューとして実施する。

---

## 入力

| データ | 参照元 |
|--------|--------|
| 変更後の実装コード全体 | worktree: `.worktree/iddue-review/{parent}/{変更ファイルパス}` |
| 関連する未変更ファイル | worktree から必要に応じて `Read`（呼び出し元・継承元・関連クラス等） |
| 変更内容（差分） | Phase 2 で取得した `gh pr diff` の出力（変更箇所の特定に使用） |
| 各サブ `implement.md` | worktree: `.worktree/iddue-review/{parent}/.iddue/orchestration/reports/{sub}/implement.md`（実装意図・handoff_notes） |

---

## 判定基準

### CRITICAL（フロー停止・COMMENT）

以下のいずれかに該当する場合：

| 問題の種類 | 例 |
|-----------|---|
| 明白なバグ | 条件分岐の誤り、nil 非考慮、off-by-one エラー |
| セキュリティ問題 | SQL インジェクション、mass assignment、認証バイパス |
| データ破壊リスク | 本番データを変更するスクリプトの誤った実行条件 |
| 重大なパフォーマンス問題 | N+1 クエリ、無限ループ、全件ロード |

### WARNING（ブロックしないが APPROVED コメントに記載）

| 問題の種類 | 例 |
|-----------|---|
| 冗長な実装 | 重複ロジック、使われていない変数 |
| 命名の問題 | 意図が読み取れない変数名・メソッド名 |
| 複雑すぎる実装 | 単純にできるのに複雑な条件式 |
| デッドコード | 到達しないコードパス |

### INFO（ブロックしない・任意の改善提案）

- より良いアプローチの提案
- Ruby/Rails のベストプラクティスに沿った書き方の提案

### OK

CRITICAL な問題がない。

---

## レビューフロー

1. 変更ファイル一覧を確認し、重要度が高いファイル（`app/`, `lib/` 配下）を優先する
2. 各変更ファイルについて **worktree のコード全体** を `Read` して確認する
   - diff は「何が変わったか」の参考として使い、コードの品質判断は全体を読んで行う
   - 変更行だけでなく、変更箇所の周辺コード・関連メソッドも確認する
3. 問題がありそうな箇所は関連ファイルも worktree から参照する
   - 呼び出し元クラス・継承元クラス・モジュールなど
   - テストファイル（`spec/` 配下）も必要に応じて参照
4. implement.md の handoff_notes に実装意図が記載されている場合は考慮する
5. CRITICAL / WARNING / INFO に分類する
6. CRITICAL が 1 件でもあれば → インライン付きコメント投稿してフロー終了（cleanup 実行）
7. CRITICAL なし → APPROVED コメント投稿（cleanup 実行）

---

## コメントフォーマット

### 問題あり（CRITICAL）

`SKILL.md Phase 4.1` の COMMENT で投稿。
原則として問題箇所の diff 行へインラインコメントを付ける。

**サマリー本文（`body`）:**
```markdown
## AI Review — 観点⑤コード品質

実装に修正が必要な問題が見つかりました。

{WARNING がある場合のみ}
### 注意（ブロックはしていないが確認推奨）

- {ファイルパス}:{行}: {WARNING の内容}
```

**インラインコメント（CRITICAL は必須、WARNING も可）:**
```json
{
  "path": "{変更ファイルパス}",
  "line": {問題の行番号},
  "body": "**[CRITICAL]** {問題の内容}\n\n{修正の提案}"
}
```

### 問題なし（全観点 OK → レビュー OK コメント）

`SKILL.md Phase 4.2` のレビュー OK コメント（`--comment`）で投稿。PR の Approve は行わない。

**コメント本文:**
```markdown
## AI Review — Issue #{parent}

すべての観点で問題なし。

| 観点 | 結果 |
|-----|-----|
| ①完了状況 | ✅ 全 {N} サブ Issue が completed |
| ②設計整合性 | ✅ config.yaml との整合確認済み |
| ③要件充足性 | ✅ 全 {N} 件の要件が充足 |
| ④CI ステータス | ✅ 全チェック passing |
| ⑤コード品質 | ✅ CRITICAL な問題なし{WARNING が N 件ある場合は「（WARNING {N} 件あり）」を付記} |

{WARNING または INFO がある場合、以下を追加}
---

### 注意・提案（ブロックしていない項目）

- {ファイルパス}:{行}: {WARNING/INFO の内容}
- {ファイルパス}:{行}: {WARNING/INFO の内容}

---

*このレビューは AI による自動レビューです。人間によるレビューでは上記に加えてビジネスロジックの正しさや将来の拡張性などを確認してください。*
```
