# 観点④: CI ステータス

## 目的

設計・要件が確認済みの前提で、CI が通っているかを確認する。
設計起因の CI 失敗は観点②で先に排除されているため、ここで検出される失敗は純粋な実装品質の問題として扱う。

---

## 入力（Phase 2 収集済みデータ）

| データ | 参照箇所 |
|--------|---------|
| CI ステータス | Phase 2.2 の `pr_info.checks` |
| PR 番号 | `pr_info.number` |

---

## 判定基準

### CRITICAL（フロー停止・COMMENT）

| 状態 | 判定 |
|------|-----|
| CI 失敗あり | CRITICAL |

### 特殊ケース: CI pending

CI チェックがまだ実行中の場合は `COMMENT` で待機を促す（SKILL.md Phase 4.3）。

### WARNING

| 状態 | 判定 |
|------|-----|
| CI は通っているが直接関係するテストファイルのカバレッジが低い疑いがある | WARNING |

### OK

全 CI チェックが passing。

---

## レビューフロー

### ステップ 1: CI ステータスの確認

Phase 2.2 で取得済みの `pr_info.checks` を確認する。

- **全チェック passing** → OK。コード品質観点へ
- **pending / waiting** → CI 完了待ちとして COMMENT 投稿して終了
- **失敗あり** → ステップ 2 へ

### ステップ 2: CI 失敗詳細の収集

スクリプトを実行して、失敗した CI チェックの詳細（アノテーション・追加ログ）を取得する。

```bash
bash .claude/skills/iddue:pr:review/scripts/fetch-ci-details.sh {pr_info.number}
```

このスクリプトは以下を行う：
- 失敗 checks のアノテーション（GitHub check-runs API）を取得
- `.claude/iddue-hooks/get-ci-failure-details.sh` が存在すれば実行し、CI プロバイダー固有の詳細ログを追加取得

フックの仕様は [`iddue/references/hooks.md`](../../iddue/references/hooks.md) を参照。

### ステップ 3: 失敗と diff を紐づける

スクリプトの出力（アノテーション・ログ）から以下を読み取る：
- どの失敗（テスト失敗、Lint エラー、型エラー等）があるか
- どのファイル・行で発生しているか

各失敗について、PR diff から原因となったコード変更を特定する：
- どの変更が失敗を引き起こしたか
- 削除・変更されたロジックによる既存テストの破損か
- 新規追加したコードのバグか

## コメントフォーマット

### CI pending の場合

`SKILL.md Phase 4.3` の COMMENT で投稿。

```markdown
## AI Review — 観点④CI ステータス

CI がまだ完了していません。CI 完了後に再度レビューを実行してください。

**ステータス**: pending
```

### 失敗あり（CRITICAL）

`SKILL.md Phase 4.1` の COMMENT で投稿。
ファイル・行が特定できる問題はインラインコメントも付ける。

**サマリー本文（`body`）:**
```markdown
## AI Review — 観点④CI ステータス

CI に失敗があります。

**ビルド**: {ビルド URL（取得できた場合）}

### 失敗（{N} 件）

| チェック名 | エラー内容 | 原因となった変更 |
|-----------|----------|----------------|
| {check名} | {失敗メッセージの要約} | {ファイル}:{行} |
```

**インラインコメント（ファイル・行が特定できる場合）:**
```json
{
  "path": "{エラーのファイルパス}",
  "line": {エラーの行番号},
  "body": "{エラー種別}: {エラー内容}\n\n{修正方法の提案}"
}
```

### 問題なし（OK → 次の観点へ）

コメント投稿はしない。内部メモとして以下を記録：

```
観点④ CI ステータス: ✅ 全チェック passing
```
