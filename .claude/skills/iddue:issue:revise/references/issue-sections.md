# Issue セクション マッピング指針

Issue 本文の各セクションと、変更が影響しやすいケースの対応表。

変更内容を本文に反映する際の参考として使用する。
必ずしも1対1のマッピングではなく、内容を全体的に把握して適切なセクションに当てはめること。

---

## セクション別 変更ガイド

### `## 概要・目的`
- **変更が必要なケース**: Issue の目的・スコープが変わった、前提となる背景が変わった
- **注意**: スコープが縮小した場合は削除する対象の記述も忘れずに除去する

### `## 実装方針`
- **変更が必要なケース**: 実装アプローチが変わった、対象ファイル・クラスが変わった、実装の詳細が判明した
- **形式**: ファイルパスと変更内容を対応させて記述するとわかりやすい

### `## 完了条件`
- **変更が必要なケース**: テスト方針が変わった、追加・削除すべき条件が判明した
- **注意**: 条件が増える場合は既存の条件と整合性が取れているか確認する

### `## 詳細`
- **変更が必要なケース**: 仕様の詳細が変わった、エッジケースが判明した

### `## 調査・参考`
- **変更が必要なケース**: 調査結果・参考情報を追記する場合

### `## 親 Issue / サブ Issue`
- **変更が必要なケース**: Issue の構成が変わった場合（通常は変更しない）

---

## 変更対象 Issue の判断基準

親 Issue が指定された場合に、各 Issue（親・サブ）が変更対象かを判断する基準。

| 変更の種類 | 親 Issue | サブ Issue |
|-----------|----------|-----------|
| 全体の目的・スコープの変更 | ✅ | 関係するサブのみ |
| 特定機能の実装方針変更 | 任意（影響範囲に応じて） | その機能を担当するサブのみ ✅ |
| 完了条件の追加・修正 | ✅（親の完了条件に影響する場合） | ✅（そのサブの完了条件に影響する場合） |
| 調査結果・参考情報の追記 | 関連する方に追記 | 関連する方に追記 |

**変更対象外と判断する場合の例:**
- そのサブ Issue がすでにクローズされている
- 変更内容がそのサブ Issue の担当範囲と無関係
- そのサブ Issue はすでに実装完了しており、変更の影響を受けない
